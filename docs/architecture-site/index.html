2. Egregore — три плоскости

Egregore — event-driven multi-agent SOC platform. Единый AgentRuntime + AgentRegistry; все сценарии через EventIngress. Логика orchestration (enqueue) — в application (EnqueueWorkerJobs, StartEngagement), не в interfaces/worker/orchestrator.py (только dequeue + execution).

ПлоскостьПутьОтветственность
Ingressinterfaces/ingress/, interfaces/api/Приём событий: CLI, FastAPI, webhooks, SIEM; RouteAndEnqueueEvent из container
Control planeinterfaces/control_plane/Critic (L2 HITL), Coordinator (narratives), bus subscribers
Worker planeinterfaces/worker/WorkerOrchestrator — dequeue only; ephemeral sandbox jobs per event/persona

Интерактивный путь: POST /v1/engagements (mode=interactive) → RunStep → AgentRunKernel → AgentRuntime. Worker path: RunWorkerJob → тот же AgentRunKernel (единый RunKernelPort).

5. Data flow: event → investigation → worker

Загрузка диаграммы…

Enqueue = application orchestration (RouteAndEnqueueEvent → EnqueueWorkerJobs). Worker = execution adapter (WorkerOrchestrator dequeue → RunWorkerJob).

  • context_builder — собирает контекст job
  • agent_executor — вызывает AgentRunKernel
  • result_validator — валидация structured output
  • finding_publisher — публикация findings в bus
  • job_finalizer — WorkerJob.transition_to, budget, metrics

correlation_id на events/jobs = investigation_id для сквозной трассировки (через CorrelationIdPort на ingress).

Очередь: единый Kafka topic worker.jobs (consumer group egregore-workers); persona в payload; чужие jobs re-enqueue. Legacy worker.jobs.{persona} deprecated.

7. Tooling & datasources

Domain-модель datasources: cys_core/domain/datasources/ — capabilities, authz, staging, write-gate. Runbook: DATASOURCES_RBAC.md. Attach-time filter + exec-time gateway check.
